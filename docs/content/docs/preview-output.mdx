The [`CameraPreviewOutput`](/api/react-native-vision-camera/hybrid-objects/CameraPreviewOutput) allows streaming a Camera feed into a Preview, which may be connected to a Preview View to display a Camera feed to the user.

### Creating a Preview Output

<Tabs items={["<Camera /> (view)", "useCamera(...) (hook)", "CameraSession (imperative)"]} groupId="api-style" persist>
<Tab value="<Camera /> (view)">
> [!NOTE]
> The [`<Camera />`](/api/react-native-vision-camera/views/Camera) view already creates a [`CameraPreviewOutput`](/api/react-native-vision-camera/hybrid-objects/CameraPreviewOutput) (+ [`<NativePreviewView />`](/api/react-native-vision-camera/views/NativePreviewView)) for you, automatically.
</Tab>
<Tab value="useCamera(...) (hook)">
```tsx
function App() {
  const device = useCameraDevice('back')
  // [!code ++]
  const previewOutput = usePreviewOutput()

  const camera = useCamera({
    isActive: true,
    device: device,
    // [!code ++]
    outputs: [previewOutput],
  })
}
```
</Tab>
<Tab value="CameraSession (imperative)">
```tsx
const session = await VisionCamera.createCameraSession(false)
// [!code ++]
const previewOutput = VisionCamera.createPreviewOutput()

await session.configure([
  {
    input: 'back',
    outputs: [
      // [!code ++]
      { output: previewOutput, mirrorMode: 'auto' }
    ],
    constraints: []
  }
], {})
await session.start()
```
</Tab>
</Tabs>

### Preview Resolution

By default, a [`CameraPreviewOutput`](/api/react-native-vision-camera/hybrid-objects/CameraPreviewOutput) chooses its own resolution. That is fine when the Preview is the only output, but as soon as other outputs are attached (e.g. a Frame Output for processing, or a Photo/Video Output for capture), their aspect ratios can disagree.

Every output is a view of the same sensor, and outputs with different aspect ratios crop the sensor area differently. The Preview may then show more (or less) to the user than your Frame, Photo or Video output can actually see.

#### Why this matters most on Android

CameraX picks a default aspect ratio per use case, and they do not agree with each other:

- Image capture and image analysis (the Frame Output) default to **4:3**.
- Video usually resolves to **16:9**.
- The Preview defaults to **4:3**.

A 16:9 video next to a 4:3 Preview therefore covers a different area of the sensor than what the user sees on screen.

On iOS this is not an issue, since every output is derived from the active format selected on the capture device - the Preview simply follows the resolved format. Android ignores [`{ resolutionBias: ... }`](/api/react-native-vision-camera/interfaces/ResolutionBiasConstraint) constraints, which is why the Preview needs its own target there.

#### Setting a target resolution

> [!NOTE]
> The Preview `targetResolution` is mainly meant for **Android**. On **iOS, do not specify it** - the Preview follows the resolved format. Instead, steer the resolution via a [`{ resolutionBias: ... }`](/api/react-native-vision-camera/interfaces/ResolutionBiasConstraint) constraint (e.g. `{ resolutionBias: videoOutput }`), see [resolution negotiation](constraints).

On Android, pick the output whose field of view matters most (e.g. the Video Output) and give the Preview the **same `targetResolution`** (or at least the same aspect ratio). The Preview is then negotiated with the session as close to that resolution as possible, so the Preview and that output cover the same field of view:

<Tabs items={["<Camera /> (view)", "usePreviewOutput(...) (hook)"]} groupId="preview-target-resolution">
<Tab value="<Camera /> (view)">
```tsx
const targetResolution = CommonResolutions.FHD_16_9

function App() {
  const videoOutput = useVideoOutput({
    targetResolution: targetResolution,
  })

  return (
    <Camera
      outputs={[videoOutput]}
      // [!code ++]
      previewTargetResolution={targetResolution}
    />
  )
}
```
</Tab>
<Tab value="usePreviewOutput(...) (hook)">
```tsx
const targetResolution = CommonResolutions.FHD_16_9

function App() {
  const videoOutput = useVideoOutput({
    targetResolution: targetResolution,
  })
  const previewOutput = usePreviewOutput({
    // [!code ++]
    targetResolution: targetResolution,
  })
}
```
</Tab>
</Tabs>

> [!NOTE]
> The `targetResolution` is a preference, not a guarantee. The Camera Session negotiates it with all other outputs, so the resulting resolution may differ. Use `onConfigurationChanged` (or `onPreviewResolution` on the [`<Camera />`](/api/react-native-vision-camera/views/Camera) view) to read the Preview's actual resolution and rotation, e.g. to size a wrapper to the Preview's exact aspect ratio and align buttons or overlays to its edges.

When omitted, the platform's default Preview resolution preference is used.

### Connecting the Preview Output to a View

To display the Camera feed to the user, you must connect the [`CameraPreviewOutput`](/api/react-native-vision-camera/hybrid-objects/CameraPreviewOutput) to a [`<NativePreviewView />`](/api/react-native-vision-camera/views/NativePreviewView):

```tsx
function App() {
  const previewOutput = usePreviewOutput()

  return (
    // [!code ++:4]
    <NativePreviewView
      style={StyleSheet.absoluteFill}
      previewOutput={previewOutput}
    />
  )
}
```

See ["Views: &lt;NativePreviewView /&gt;"](nativepreview-view) for more information about `<NativePreviewView />`.
